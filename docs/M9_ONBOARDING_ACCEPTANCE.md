# M9 情境化早期航程引导验收

> 日期：2026-07-24
> 版本：`0.22.8`
> 状态：`APPROVED`（纯领域目标、桌面/窄视口 HUD、真实运行态与软件合成帧闭环；无说明玩家理解度仍属外部门禁）

## 目标

新航次不再依赖静态操作说明解释前期流程。HUD 只呈现当前世界问题、可核对的资源缺口和已经发生的进度，由既有漂流物、制作、放置、设备交互和危险反馈承担实际教学。

- 不显示按键清单、开发者术语或测试文案；
- 不新增教程存档字段、任务奖励或绕过领域事务的完成标记；
- 不抢占鲨鱼、风暴、入水和登岛等高优先级反馈；
- 完成第一杯淡水与首块扩筏后自动退出，不长期占据 HUD。

## 领域合同

`src/game/domain/onboarding.ts` 的 `getVoyageObjective()` 只消费当前背包、饥渴、筏格数和净水器反馈，每次渲染重新推导目标：

1. 新航次先核对潮汐净水器所需 `4 漂木 / 2 聚合片 / 1 绳索`；
2. 已装配套件后转为筏面部署；
3. 已部署后依次处理容器、燃料、冷凝、完成收取；
4. 第一杯淡水形成后转入建造锤和首块扩筏；
5. 口渴 `<=30` 或饥饿 `<=24` 且背包有补给时，临时优先显示可用供给；
6. 筏格超过起始 3x3 后返回 `null`，HUD 自动收起。

成本进度按各项所需单位求和，不把单一稀缺材料掩盖在“总材料数”里；显示名直接复用 `ITEM_DEFINITIONS.shortName`，不会与背包产生第二套物品名称。

## HUD 接线

- `Hud.tsx` 使用既有 Lucide 图标、语义色和 3px 进度轨，不新增位图资产；
- 目标卡宽度桌面 224px、窄视口 210px，使用两列稳定网格和可换行资源行；
- 当信号面板出现时目标卡下移；鲨鱼活动、漂浮鲨体、强风暴、玩家入水或上岛时目标卡直接让位；
- 目标卡没有指针事件，不会截获视角锁定、工具点击或世界交互；
- `aria-label` 汇总阶段、目标和资源真值，但动态资源计数不使用 `aria-live` 连续打断读屏。

## 外部门禁

- 3 至 5 名无说明新玩家能否从世界反馈理解“打捞 -> 净水 -> 扩筏”，以及首次完成三阶段所需时间；
- 目标真实 GPU 下 1280x720/30 与 1920x1080/60 的字重、背景模糊、运动中可读性和色觉模式；
- 键鼠重映射、字幕和减少动态组合下的辅助技术复核；
- 后续烹饪、鲨鱼预兆和首次岛屿流程是否需要同类情境目标，必须依据无说明玩家证据决定，不能继续堆叠常驻卡片。
